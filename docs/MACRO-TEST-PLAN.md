# mado — Macro Refactor & Testing Program

> Generated 2026-05-31 by a 4-agent survey workflow (macro-refactor sites · test-macro design · config-permutation+conformance harness → sequenced plan). Companion: [GAP-ANALYSIS.md](./GAP-ANALYSIS.md), [REMEDIATION-PLAN.md](./REMEDIATION-PLAN.md). Realizes the PRIME DIRECTIVE (macros everywhere via the tatara-rust-ast EMITTER SUBSTRATE) + the proven-foundations testing floor.

## Overview

Three surveys converge on one shape: mado hand-writes the same boilerplate the pleme-io substrate already has (or should have) typed surfaces for — paired enum match-tables (round-trip), unit-enum constant tables, two byte-identical FIFO histories, ~70 near-clone VT `#[test]` bodies, brittle byte-substring response asserts, and a config test suite that spot-checks ~12 enum cases instead of the full Cartesian product. The destination (CSE / Pillar 12): every recurring impl is a farm Spec, every recurring test family is a verification-matrix forcing-function, the config space is enumerated mechanically not by hand, and VT correctness is proven against an esctest/vttest conformance floor driven through the existing headless scenario engine. Because the highest-leverage primitives are missing FROM THE FARM (a paired enum round-trip derive, a ClosedAxis derive, a consumable verification-matrix test-emitter, and a shikumi permutation-cube builder), the plan lands those FIRST — each new fleet primitive, not a mado one-off — then refactors mado derive-by-derive in green reviewable waves, then macro-izes the tests, then stands up the permutation + conformance suites that the new primitives make trivial. Verified against source: the farm's four spec kinds (PerField/PerVariant/Newtype/EnumFold + MacroCatalogSpec) are live but PerVariantDeriveSpec carries no per-variant rename/alias attribute (the round-trip gap is real); shikumi::ClosedAxis/ProductCube exist but have no generic cube builder (every cube is hand-authored); shikumi::ConfigCoverage::assert_every_field_consumed is ready to wire; mado already consumes pleme-invalidating-setter-derive (canonical farm consumer) but NOT tatara-rust-snapshot despite the ★★ TOKEN-STABILITY directive; PromptHistory and UserMarkHistory are confirmed structural twins. Net removable boilerplate across the surveys: ~500 LOC of impl/test in the macro-refactor area, ~1100-1400 LOC in the terminal test module, ~40 hand-enumerated config asserts replaced by ~3 matrix tests covering the full 2560-cell × 3-tier product, plus a ConfigCoverage test that immediately surfaces ≥6 dead-knob groups (selection/search/quick_terminal/shaders/shell_integration/profiles).

## Farm extensions — land these FIRST (fleet primitives, not mado one-offs)

- FromStrKind / AsStrKind paired round-trip derive — PerVariantDeriveSpec extended with a per-variant attribute. SPEC KIND: PerVariantDeriveSpec (the existing per_variant.rs emitter) extended with a NEW per-variant proc-attr `#[kind(name="...", alias="...", byte=0xNN)]` carried via tatara-rust-proc-attr. Emits `fn parse(&str)->Option<Self>` (canonical name + every alias arm) + `fn as_kind_str(self)->&'static str` (canonical render) and, when `byte=` present, `from_byte(u8)->Option<Self>`/`as_byte(self)->u8`. Catalog entry ships the round-trip unit test (`for v in Self::ALL { assert_eq!(parse(as_kind_str(v)), Some(v)) }`) per CATALOG REFLECTION. HIGHEST-LEVERAGE: ≥6 mado consumers (PointerShape, ClipboardKind, PromptKind, Placement, Action, DiscoveryOutcome::kind). Published as pleme-kindstr-derive (or pleme-roundtrip-derive). This is the canonical mado-first farm gap — author it FIRST.
- ClosedAxis derive — emits `const ALL: &[Self]` + `impl shikumi::ClosedAxis` (Copy+Eq+Hash bounds) for any unit enum. SPEC KIND: PerVariantDeriveSpec with `variant_shape = Unit` + an `impl_prelude` that writes the `impl shikumi::ClosedAxis` block referencing the emitted ALL slice (composes with existing allvariants — ClosedAxis is allvariants targeting the shikumi trait rather than an inherent ALL). Published as pleme-closedaxis-derive. Lets mado's 6 closed config enums (CursorStyle, TearMode, TearRuntime, MouseShiftCapture, ColorblindMode, QuickTerminalEdge) plug into shikumi::axis_iter with zero hand-written ALL.
- VerificationMatrix test-emitter macro — the FIRST test-generation primitive in the farm (the farm ships only impl derives today). SPEC KIND: NEW declarative-macro catalog entry (tatara-rust-macro-rules crate) authored as `pleme-verification-matrix`, NOT a proc-derive. Expands a typed `const ROWS: &[Row]` table into (a) one `#[test] fn` per row and (b) a `matrix_covers_all` build-gate that asserts `ROWS.len()` (or the covered set) equals an enum's variant count via the existing pleme-variantcount-derive — composing TWO farm primitives. This is CLOSED-LOOP MASS-SYNTHESIS rule 1 (verification-matrix-as-forcing-function) made consumable; mado is the third+ consumer after pleme-doc-gen's 37-row matrix and caixa-forge. The five mado matrices (vt_case!/sgr_matrix!/dec_mode_matrix!/osc_matrix!/cursor_style_matrix!) are thin domain wrappers over it.
- TieredPermutationCube macro — `shikumi::perm_cube!{ A, B, C, ... }` that mechanically emits the product struct + `const ALL` (Cartesian nested-loop) + `impl ClosedAxis` + `impl ProductCube` (is_realizable=true for independent axes). SPEC KIND: NEW shikumi-side declarative macro (lives in shikumi, not the proc-macro farm, because it targets shikumi's own ClosedAxis/ProductCube traits). Removes the bespoke-struct-per-cube boilerplate that ProductCube requires today (cube.rs confirms there is no generic builder). Fleet-wide: every shikumi TieredConfig consumer (mado/tear/frost/tend/kikai/kurage/namimado) wants this. Pairs with a sibling `shikumi::tiered_permutation_test!{ Config, axes=[...], consumed=CONSUMED_FIELDS, apply=|cfg|... }` that fuses cube-iter + 3-tier loop + serde round-trip + ConfigCoverage + apply-closure + failure-aggregation into one matrix #[test].
- BoundedEvictHistory<M: HasGridRow> — generic VecDeque-backed FIFO with cap + record-with-back-dedup + shift_on_evict + len/is_empty/clear/iter. SPEC KIND: NOT a derive — a shared library TYPE lifted into todoku or hayai. PromptHistory (prompt_mark.rs) and UserMarkHistory (osc_1337.rs) are confirmed byte-identical structural twins (VecDeque + cap + record + shift_on_evict, same tests). Second occurrence in one repo = extract now per three-site rule; the row-shift bookkeeping on scrollback eviction is the load-bearing shared logic. mado keeps only the per-mark payload type (PromptMark/UserMark) + the HasGridRow impl.

## Sequencing

Farm-extensions-first is non-negotiable: F1 (round-trip derive), F2 (ClosedAxis derive + shikumi perm-cube/tiered-test macros), and F3 (VerificationMatrix test-emitter) are the primitives EVERY downstream wave consumes, and each is a fleet primitive (published crate / shikumi addition) rather than a mado one-off — per Pillar 12 and the EMITTER-SUBSTRATE rule, you extend the farm FIRST then consume. They are independent of each other and of mado, so they can land in parallel; each is self-contained, gated by its own farm `cargo test` + catalog-reflection tests, and touches zero mado code, so none can break mado. F1 ships before M1/M2 (its consumers), F2 before M2/C1, F3 before M5. The macro refactor (M1→M3) is sequenced derive-by-derive so every wave compiles and tests green and the diff stays small and reviewable: M1 is three isolated round-trip files; M2 is the remaining round-trip + the six config enums getting ClosedAxis (which C1 later needs); M3 is accessor/newtype boilerplate + the BoundedEvictHistory extraction (two commits) + the explicit CellAttrs-bitflags decision (adopt `bitflags`, never hand-roll a third copy). Each enum/struct is its own delete-match-add-derive with behavior preserved by the pre-existing tests, so review is read-the-derive-line not read-the-implementation. Test macros come AFTER the refactor so the matrices assert against the already-cleaned types: M4 first (typed VtResponse + tatara-rust-snapshot adoption is the prerequisite for the response-byte family and satisfies the ★★ TOKEN-STABILITY directive mado currently violates), then M5 lands the five VT matrices one-per-commit each with a covers-all build-gate (the forcing function that makes the green matrix the substrate's promise to operators), then M6 folds the low-priority proptests. The permutation + conformance suites come LAST because they depend on the new primitives + the cleaned enums: C1 needs F2's perm-cube + M2's ClosedAxis enums and intentionally lands ConfigCoverage RED to surface the ≥6 dead-knob groups as real signal; C2 grows the VT conformance corpus through the existing headless scenario engine (no new engine) so a new case is a dropped YAML, and adds the config×VT smoke cross-product. Every wave ends on `cargo test` green; no wave is a giant unreviewable diff because the farm work is isolated upstream, the refactor is one typed concept per commit, and the test/permutation work is additive (new test files + folded bodies) rather than a sweeping rewrite. The one cross-wave guardrail: M5's matrices and C2's corpus are what protect the M3 CellAttrs/bitflags migration and the M1-M2 round-trip folds from silent behavior drift, so they must not be skipped or deferred past a release.
